3. Skema Data

3.1 Whitelist Staf

Untuk versi awal (MVP), whitelist disimpan sebagai environment variable WHITELIST_CHAT_IDS (comma-separated). Ini cukup untuk jumlah staf kecil dan menghindari kebutuhan database tambahan. Jika daftar staf berubah, admin PPID redeploy dengan env var baru.

// src/middleware/whitelist.ts
interface WhitelistEntry {
  chatId: string;
  staffName?: string;   // opsional, untuk audit log lebih terbaca
}

function isWhitelisted(chatId: string, whitelist: string[]): boolean {
  return whitelist.includes(chatId);
}
Jika ke depan staf bertambah banyak atau butuh role (admin vs staf biasa), pindahkan ke Google Sheet terpisah ("Staff Registry") yang dibaca saat startup — tapi ini di luar scope MVP.

5. Alur Chunking Audio (Detail Implementasi)

// src/audio/chunker.ts
import ffmpegPath from 'ffmpeg-static';
import { path as ffprobePath } from 'ffprobe-static';
import ffmpeg from 'fluent-ffmpeg';

ffmpeg.setFfmpegPath(ffmpegPath as string);
ffmpeg.setFfprobePath(ffprobePath);

async function getDurationSeconds(filePath: string): Promise<number> {
  return new Promise((resolve, reject) => {
    ffmpeg.ffprobe(filePath, (err, metadata) => {
      if (err) return reject(err);
      resolve(metadata.format.duration ?? 0);
    });
  });
}

async function splitIntoChunks(
  filePath: string,
  chunkMinutes: number,
  outputDir: string
): Promise<string[]> {
  const duration = await getDurationSeconds(filePath);
  const chunkSeconds = chunkMinutes * 60;
  const chunkPaths: string[] = [];
  const totalChunks = Math.ceil(duration / chunkSeconds);

  for (let i = 0; i < totalChunks; i++) {
    const outputPath = `${outputDir}/chunk_${i}.mp3`;
    await new Promise<void>((resolve, reject) => {
      ffmpeg(filePath)
        .setStartTime(i * chunkSeconds)
        .duration(chunkSeconds)
        .audioChannels(1)          // mono, sesuai rekomendasi Whisper
        .audioFrequency(16000)     // 16kHz
        .audioBitrate('32k')
        .output(outputPath)
        .on('end', () => resolve())
        .on('error', reject)
        .run();
    });
    chunkPaths.push(outputPath);
  }
  return chunkPaths;
}

// Proses SATU segmen per waktu (bukan Promise.all paralel)
// untuk menghindari OOM di Render Free (512MB RAM, 0.1 CPU) - lihat PRD §4
Penting: chunk diproses sekuensial (satu per satu dengan await di dalam loop), bukan paralel. Memproses banyak chunk sekaligus di instance 512MB RAM berisiko OOM.

6. Prompt System

6.1 Intent Parsing (Mode 1 - Pencarian Arsip)

Kamu adalah asisten pencarian arsip untuk Kesekretariatan PPID.
Tugasmu HANYA menerjemahkan perintah staf menjadi parameter pencarian metadata dokumen.

Aturan:
- Jangan mengklaim bisa mencari ISI dokumen, hanya metadata (nama file, tanggal, jenis).
- Jika perintah ambigu (mis. tidak jelas tahun/jenis dokumen), tanyakan klarifikasi singkat sebelum memanggil tool search_archive.
- Selalu gunakan tool search_archive untuk pencarian, jangan menjawab dari pengetahuan umum.
- Jika hasil pencarian kosong, sampaikan dengan jelas dan sarankan staf mencoba kata kunci lain.

Bahasa respons: Bahasa Indonesia, singkat dan profesional.

6.2 Sintesis Notulen (Mode 2 - Notulen Rapat)

Kamu adalah asisten penyusun draf notulen rapat untuk Kesekretariatan PPID.
Kamu akan menerima transkrip mentah hasil speech-to-text dari rekaman rapat.

Tugasmu: susun draf notulen terstruktur dengan format berikut (dalam Bahasa Indonesia):

1. Judul/Topik Rapat (jika disebutkan dalam rekaman, jika tidak tulis "Tidak disebutkan")
2. Poin Pembahasan (bullet list, ringkas per topik yang dibahas)
3. Keputusan yang Diambil (bullet list, hanya yang eksplisit disepakati)
4. Tindak Lanjut / Action Item (format: [Tugas] - [Penanggung Jawab jika disebutkan])

Aturan penting:
- JANGAN mengarang informasi yang tidak ada di transkrip. Jika suatu bagian tidak jelas dari
  rekaman (mis. penanggung jawab tidak disebutkan), tulis "tidak disebutkan" alih-alih menebak.
- Transkrip hasil STT bisa mengandung kesalahan pengenalan kata, terutama istilah teknis atau
  nama orang/instansi. Beri catatan di akhir notulen: "Draf ini dihasilkan otomatis dan PERLU
  diverifikasi manual sebelum difinalisasi."
- Jangan menyimpulkan sentimen atau menilai kualitas rapat, hanya rangkum faktanya.

8. Batasan yang Wajib Diketahui AI Coding Agent

  • Render Free spin-down 15 menit idle — jangan asumsikan service selalu "warm" saat testing manual.
  • File audio wajib dihapus (fs.unlinkSync) setelah diproses, termasuk semua file chunk sementara — bukan hanya file asli.
  • Pencarian arsip adalah metadata search, bukan semantic search — jangan implementasikan embedding/vector search kecuali diminta eksplisit di iterasi berikutnya.
  • Proses notulen untuk file besar berjalan asinkron — bot harus membalas "sedang diproses" dalam <3 detik sebelum mulai transkripsi, bukan menahan response Telegram sampai selesai.
  • Chunking audio diproses sekuensial, bukan paralel (lihat §5).
